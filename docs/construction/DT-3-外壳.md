## DT-3：外壳

状态：已完成（2026-10-30）。Linux 上手测过；macOS、Windows 三平台 CI 编译、测试过，网页视图里的行为（通知、托盘、菜单）等 DT-6 出安装包再手测。

### 目的

照 `docs/blueprint/desktop.md` 写出桌面端的外壳 `miyu-desktop`：一个窗口开网页软件给的本机地址，关窗口藏进托盘，托盘「退出」连核心一起停。三个平台都编得过、测试过，Linux 上本机手测一遍，正式版量藏着时的内存。

### 蓝图改哪几节

- `docs/blueprint/desktop.md`：写的时候发现和图纸不一样的地方照实改（「怎么走」第 12 条 macOS 的应用菜单自己建，见「要拍板的」）。

### 要拍板的

- macOS 的 `⌘Q`：彻底退出，和托盘「退出」同一条，连核心停（项目主人 2026-10-30 定）。
- macOS 的应用菜单外壳自己建：「退出 Miyu」（`⌘Q`）走彻底退出，「编辑」一栏用系统的（复制、粘贴、全选这些），「窗口」一栏的关闭同关窗口。Tauri 默认的菜单里「退出」直接退外壳、不经外壳的退出那一条，所以不用它。

### 不做什么

- 图标：先用原图缩的占位图标，DT-5 换。
- 安装包：DT-6。这一步 CI 只编译、clippy、测试。
- macOS、Windows 的通知：等 CI 出的程序实测，接不住的记下来找网页。

### 验收

1. 纯逻辑的单测（导航、读那一行 JSON、找主程序、下载的名字、三份字）改代码之前是红的。
2. 本机 Linux 手测：开窗口免密进来；外链交系统浏览器；下载进「下载」目录；关窗口藏起来、托盘「显示 Miyu」拿回来；第二次开程序叫回窗口；藏着时页面照旧弹通知、点通知拿回窗口；托盘「退出」核心停了（`run/core.lock` 放了）、外壳退了；`miyu` 找不到、`miyu web` 出错时弹对话框。
3. release 版藏着 5 分钟的内存（外壳、网络进程、网页进程的 Pss 合计）记在这里。
4. CI 三平台编译、clippy `-D warnings`、测试全绿；每个 `.rs` 不超过 500 行。

### 风险

- Linux 上没有 `libayatana-appindicator` 的建不出托盘：记一行日志、照旧开窗口，没托盘时靠再开一次程序叫回窗口。
- 窗口状态插件把「藏着」也记下来，下次起来窗口不出来：只记大小、位置、最大化。

### 结果

本机：Arch，niri（Wayland），webkit2gtk-4.1 2.54.1；外壳 release 版；核心 main 33139c73d、网页 main ec07b57c（动画四处改过的那一版，W-982）；沙箱数据根，网页软件的口子 8811（这台机器上 8300 被别的程序占着）。窗口用 niri 的自动化座位截图、点击，托盘菜单用 dbusmenu 的 `Event` 点。

| 项 | 结论 | 依据 |
|---|---|---|
| 免密进来 | 行 | `miyu web` 第一次 100 毫秒、以后 20 到 40 毫秒；页面直接到引导的欢迎屏，不出设访问密码那一屏 |
| 关窗口 | 行 | niri 发关闭请求，窗口藏起来，进程留着 |
| 第二次开程序 | 行 | 第二个进程 137 毫秒退出（退出码 0），第一个的窗口拿回来，页面状态还在、没再要网址 |
| 托盘「退出」 | 行 | 菜单两项「显示 Miyu」「退出」（照系统语言）；点「退出」外壳 217 毫秒退出，核心停了（运行日志 `stopped reason=request`，`run/core.lock` 放了） |
| 找不到主程序 | 行 | 弹「找不到 Miyu 的主程序」，只有「退出」，点了外壳退出 |
| `miyu web` 出错 | 行 | 碰上装在 `/usr/bin` 的旧版 `miyu`（不认 `--print`）：弹「打不开 Miyu 的页面」加它的报错原话，「重试」「退出」 |
| 外链（同一页、新窗口、`window.open`） | 行 | 都交给 `xdg-open`（换成只记日志的假程序），窗口不动 |
| 同来源的新窗口 | 行 | 交系统的浏览器 |
| 同来源的页面 | 行 | 在窗口里开 |
| `file:` 链接 | 行 | 没开，也没交出去（WebKit 在外壳之前就挡了） |
| 下载 | 行 | `<a download>` 存进「下载」目录，第二次叫 `note (1).txt`；blob 的也存下了 |
| 通知权限 | 行 | 页面里有 `Notification`，`requestPermission()` 回 `granted` |
| 剪贴板 | 行 | `navigator.clipboard.writeText` 成 |
| 藏着时弹通知、点通知 | 行 | 页面 5 秒后 `new Notification`，其间把窗口关掉：通知照样弹在 mako 里（带 `default` 动作）；用 `makoctl invoke` 点它（mako 发 `ActionInvoked`，和鼠标点同一条路），窗口拿回来，页面的 `onclick` 也收到了。连试三次都行；更早一次（没加日志的那一版）点了没反应，DBus 上 `ActionInvoked` 发出去了、WebKit 没接，之后没再复现，日志里通知弹出、被点、关掉各记一行，再出现时查得到 |
| 刷新 | 没有 | 窗口里按 F5 不刷新（网页视图没有浏览器的快捷键）；页面自己有重连，第一版不加 |

内存（外壳加 WebKit 子进程的 Pss 合计）和 CPU：

| 时刻 | 合计 | 外壳 | 网络进程 | 网页进程 | DT-1（debug 版、动画没改） |
|---|---|---|---|---|---|
| 显示时（欢迎屏） | 376 MiB | 106 MiB | 26 MiB | 244 MiB | 715 MiB |
| 藏起来 5 分钟 | 272 MiB | 88 MiB | 17 MiB | 167 MiB | 404 MiB |

藏着时 10 秒里三个进程一个时钟滴答都没用。

手写变异九个都被单测逮住：别的口子也算同来源、新窗口留在窗口里、`file:` 也交出去、重名不加编号、名字带路径照留、不是本机地址也收、被信号杀掉的当成功、不看外壳旁边、日文认不出。

三平台 CI（格式、clippy、测试、行数、正式版）全绿。

### 碰到的

- 这台机器 8300 被别的程序占着时，`miyu web` 报「端口 8300 已被占用」，提示用 `--port`。桌面端用户改不了参数，只能去配置里改 `web.port`：转给网页的会话看要不要在默认口子被占时自己换一个。
- 沙箱里要先把网页包装进数据根（核心才认 `web.*` 配置项）。开发时的事，装好的不会这样。
- 没测：托盘左键（Linux 本来就收不到）。
